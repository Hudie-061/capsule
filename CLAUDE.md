# Capsule — капсульный гардероб: контекст проекта

Этот файл — передача контекста из чата с Claude, где мы обсуждали продукт, рынок и дизайн.
Положи его в корень репозитория `Hudie-061/capsule`: Claude Code читает `CLAUDE.md` автоматически.
Общение и интерфейс — на русском.

## 1. Что это за продукт

Приложение для себя и друзей. Пользователь фотографирует свою одежду, ИИ вырезает вещи с фона
и каждый день собирает из них образы. Приложение подсказывает, чего не хватает гардеробу,
и где это купить дешевле всего.

**Главная ставка владельца:** режим покупок «одеваться круто и экономить деньги». Именно он должен
цеплять пользователя. Образы дня и замена вещей — ежедневная привычка, которая приводит в покупки.

**Стадия:** закрытый тест с друзьями. Вход по коду доступа — временное решение. Если проект вырастет,
переходим в официальные сторы и на нормальные аккаунты.

## 2. Стек и устройство (по коду репозитория)

- Форк `tandpfun/wardrobe` (MIT). React 19 + Vite 6, Capacitor 8 (Android APK), Vitest.
- Данные пользователя (вещи, фото, оценки, профиль) хранятся только на устройстве (`src/lib/db.js`).
- Деплой: GitHub Actions → GitHub Pages (`https://hudie-061.github.io/...`) + сборка APK (`.github/workflows/android.yml`).
- ИИ: приложение → Cloudflare Worker `capsule-proxy` (`proxy/worker.js`) → Gemini API.
  - Ключ Gemini лежит только в секретах Worker. У друзей коды доступа (`ACCESS_CODES` = `name:code,...`).
  - Worker сам строит все промпты, фиксирует модели, отвечает только на темы одежды. Это обязательное требование: прокси не должен работать как универсальный чат-бот или генератор картинок.
  - Задачи Worker: `detect`, `cutout`, `modeled`, `tryon`, `plan`, `gaps`, `learn`, `palette` + `GET /status`.
  - Переменные: `ALLOWED_ORIGINS`, `TEXT_MODEL`, `IMAGE_MODEL`, `DAILY_TEXT_LIMIT`, `DAILY_IMAGE_LIMIT`, `MONTHLY_IMAGE_BUDGET`. KV-привязка: `USAGE`.
- Клиент прокси: `src/lib/gemini.js`. Настройки (адрес сервера + код): `src/lib/settings.js`, `src/settings-panel.jsx`.

### Распространение
- **iOS (друзья на iPhone):** веб-версия через Safari → «Поделиться» → «На экран Домой». Бесплатно. TestFlight требует Apple Developer Program ($99/год) и Mac — пока не нужно.
- **Android:** APK из GitHub Actions. В 2027 году Google расширит обязательную верификацию разработчиков на все страны. Тогда понадобится аккаунт «limited distribution», иначе ставить можно будет только через ADB или «расширенную» установку.

## 3. Текущая проблема (16.11.2026): «Нет связи с сервером» при входе на ПК

- Worker жив: GET на корень отвечает `{"error":"Invalid access code"}`.
- «Нет связи» клиент показывает только при `Failed to fetch`, то есть ответ заблокирован браузером.
- **Главный подозреваемый: не привязан KV `USAGE`.** Worker настраивали через дашборд, а не через wrangler, а `/status` обращается к `env.USAGE` вне try/catch. Без привязки Worker падает и отдаёт страницу ошибки Cloudflare без CORS-заголовков.
  - Исправление: Cloudflare → KV → создать namespace → Worker → Settings → Bindings → KV namespace, имя переменной ровно `USAGE` → Deploy.
  - Проверка: Observability/Logs, ошибка вида `Cannot read properties of undefined (reading 'get')`.
- В `MONTHLY_IMAGE_BUDGET` в дашборде стоит `"\t140"` (символ табуляции). Заменить на `140`.
- Если сайт открывается с `http://localhost:5173` (`npm run dev`), этот адрес надо добавить в `ALLOWED_ORIGINS`.
- **Предлагаемое улучшение кода:** обернуть весь обработчик в `fetch` (включая `/status`) в try/catch, который всегда возвращает JSON с CORS-заголовками. Добавить понятную ошибку, если `env.USAGE` не настроен.
- **Сделано в коде (16.11.2026):** try/catch с CORS, понятные ошибки про KV `USAGE`, `GEMINI_API_KEY`, `ACCESS_CODES` и чужой origin (403 с адресом), пробелы в `ACCESS_CODES` и `/` в `ALLOWED_ORIGINS` больше не ломают вход. Клиент отличает «сервер недоступен» от «браузер скрыл ответ». Проверка 16.11: CORS для `https://hudie-061.github.io` и `https://localhost` настроен верно, `http://localhost:5173` в `ALLOWED_ORIGINS` нет. Владельцу осталось привязать KV и вставить новый `proxy/worker.js` в Worker.

## 4. Продуктовые решения владельца

Решено:
- **Утро или вечер:** пользователь выбирает, когда получать образ — утром на сегодня или с вечера на завтра (многие собираются с вечера). Есть вариант «Оба раза».
- **Замена любой вещи в образе:** нажал на вещь (например, джинсы) → снизу выезжает список подходящих вещей из своего гардероба → выбранная подставляется в образ.
- **Покупки — отдельный режим и главная ставка:** «Чего не хватает капсуле» → предложения магазинов, отсортированные по цене **с доставкой**, фильтр «Новые / Б/у», бейдж лучшей цены и экономии, счётчик «Сэкономлено за месяц».
- **Карточка образа переворачивается** (3D flip) и показывает образ на человеке:
  - режим «Манекен»: нажатие на манекен показывает выноски с линиями к каждой вещи («Белая футболка», «Синие джинсы», «Чёрные кроссовки»); нажатие на выноску открывает ту же замену вещи, и новая вещь сразу появляется на манекене, переворачивать карточку обратно не нужно;
  - режим «На мне» — «Примерь на себе»: фото в полный рост → ИИ-примерка (в Worker уже есть задача `tryon`).
- **Названия вещей в формате «цвет + тип»:** «Чёрный бомбер», «Синие джинсы». Закрепить в промпте распознавания.
- **Примерочная «На мне» (16.11.2026, после первого теста):** с фото человека берём только лицо и фигуру, его одежду игнорируем; вещи передаются списком (тип, название, цвет, детали) в порядке слоёв, добавлять или менять вещи нельзя; поза всегда одна (прямо, лицом к камере, руки вдоль тела, в полный рост), фон — светлая студия. Фото в карточке показывается целиком (без обрезки), по тапу — на весь экран. Идеи на потом: базовое «студийное» фото пользователя один раз для одинаковой позы во всех примерках; смена фона за отдельную картинку.
- **Бренд вещи** пользователь пишет сам (поле «Бренд» в карточке вещи и при импорте); стилист видит бренды в каталоге.
- **Палитра («Моя палитра»):** по готовому промпту и селфи — цветотип, лучшие цвета, цвета, которых избегать у лица, металл и украшения. Карточкой можно поделиться в сторис, кнопка «Найти вещи в моих цветах» ведёт в «Покупки».
- **Кнопка полной перегенерации образа на сегодня** («Другой образ») — на будущее, в макете уже есть.
- **Оценка образов:** лайк или дизлайк + причины в один тап (уже в коде: `feedback`, `learn`). От 10-балльной шкалы решили отказаться: шумные данные и лишнее трение. Возможный вариант — вечерний вопрос «Как тебе было в образе?» с 3 вариантами ответа.

## 6. Поиск лучшей цены: как реализовать

Новая задача Worker, например `prices`:
1. Gemini превращает недостающую вещь (из `gaps`) или фото в точный поисковый запрос: тип, цвет, крой, материал.
2. Поиск товаров: **SerpApi** (Google Shopping / Google Lens) даёт структурированные цены в JSON, 250 запросов в месяц бесплатно, тариф ~$75 за 5000. Альтернатива — Gemini с Google Search grounding (5000 запросов в месяц бесплатно, дальше $14 за 1000, но цены текстом и менее надёжны).
3. Регион Бельгия, сортировка по цене **с доставкой**, топ 3–5 предложений.
4. Кэш на 24 часа в KV, лимиты по коду доступа.
5. Монетизация потом: партнёрские ссылки магазинов (сети вроде Awin).

Проверь актуальные цены на API перед запуском. ИИ-примерка: генерация изображения порядка нескольких центов за картинку, кэшировать результат на каждый образ. Фото пользователя хранить на устройстве.

## 7. Рынок (кратко)

Конкуренты: Whering (10M+ пользователей, фримиум + B2B с брендами), Alta (бесплатно + партнёрские ссылки + B2B, $20M Series A в октябре 2026), Acloset (бесплатно до 100 вещей), Fits, Indyx (живые стилисты), Style DNA (цветотип), Cladwell, Stylebook.
Главная причина ухода пользователей — долгая загрузка гардероба. Идеи против этого: несколько вещей на одном фото (Gemini делит), видео шкафа, импорт покупок, каталог типовых вещей, первый образ уже после 3–5 вещей.

## 9. Правила работы

- Владелец сам просматривает файлы на вредоносный код: объясняй изменения, не добавляй зависимости без причины, называй каждую новую библиотеку.
- Никогда не клади ключ Gemini или коды доступа в код приложения, коммиты или логи.
- Все промпты и выбор моделей остаются в Worker. Ограничение «только одежда» не ослаблять.
- Перед коммитом запускать `npm test` и `npm run build`.
