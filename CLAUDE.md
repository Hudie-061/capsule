## 1. Что это за продукт

Приложение для себя и друзей. Пользователь фотографирует свою одежду, ИИ вырезает вещи с фона
и каждый день собирает из них образы. Приложение подсказывает, чего не хватает гардеробу,
и где это купить дешевле всего.

**Главная ставка владельца:** режим покупок «одеваться круто и экономить деньги». Образы дня и замена вещей — ежедневная привычка, которая приводит в покупки.

**Стадия:** закрытый тест с друзьями. Вход по коду доступа — временное решение. Если проект вырастет, переходим в сторы и на аккаунты.

## 2. Архитектура (как устроено сейчас)

```
Телефон / ПК (React 19 + Vite 6; APK через Capacitor 8)
  всё хранится на устройстве (IndexedDB)  ──X-Access-Code──▶  Cloudflare Worker capsule-proxy  ──▶  Gemini API
                                                               (промпты, модели, лимиты, KV USAGE)  ──▶  SerpApi (цены)
```

- Форк `tandpfun/wardrobe` (MIT). Сервер оригинала перенесён в браузер: `src/lib/local-api.js` (те же REST-маршруты `/api/import/...`, вызываются через `localFetch`), `src/lib/image.js` (chroma-key на canvas), `src/lib/db.js` (IndexedDB: `kv` + `blobs`).
- **Worker** (`proxy/worker.js`) — единственное место с ключами, промптами и выбором моделей. Задачи: `detect`, `cutout`, `modeled`, `tryon`, `plan`, `gaps`, `learn`, `palette`, `prices`, `offer` + `GET /status`. Виды лимитов: `text`, `image`, `search` (в день на человека) + месячные бюджеты на всех (`image`, `search`). Кэш цен в KV на 24 ч, повторный запрос из кэша бесплатен (`peek`).
  - Секреты: `GEMINI_API_KEY`, `ACCESS_CODES` (`имя:код,...`), `SERPAPI_KEY` (необязательно). Переменные: `ALLOWED_ORIGINS`, `TEXT_MODEL`, `IMAGE_MODEL`, `DAILY_TEXT_LIMIT`, `DAILY_IMAGE_LIMIT`, `DAILY_SEARCH_LIMIT`, `MONTHLY_IMAGE_BUDGET`, `MONTHLY_SEARCH_BUDGET`. KV-привязка: `USAGE`.
  - Любой ответ — JSON с CORS; понятные ошибки про KV, ключи, чужой origin (403 с адресом), `code` для машинной обработки (`origin_not_allowed`, `setup`, `prices_not_configured`).
- **Клиент Worker:** `src/lib/gemini.js` (`call`/`task`, объяснение «Failed to fetch»: сервер недоступен vs браузер скрыл ответ).
- **Экраны:** `src/App.jsx` (оболочка, нижнее меню, гардероб и карточка вещи), `src/today.jsx` (образ дня), `src/shopping.jsx`, `src/palette.jsx`, `src/timing.jsx`, `src/settings-panel.jsx` (Профиль), `src/onboarding.jsx`, `src/import-flow.jsx` («＋»).
- **Общее:** `src/ui.jsx` (иконки, силуэты вещей по типу, `Segmented`, `Sheet`), `src/v2.css` (весь дизайн v2), `src/styles.css` (базовые токены + стили карточки вещи из оригинала), `src/import-flow.css` (стили оригинала, переопределены в v2.css).
- **P2/P3:** `src/lib/countries.js` (страны, валюты, сайты б/у), `src/lib/sizes.js` (оценка мерок, размеры), `src/lib/style-options.js` (варианты для квиза и профиля), `src/sizes.jsx` + `src/body3d.jsx` (мерки, размерная сетка `sizeChart`, 3D-тело).
- **3D-тело:** `src/assets/mh-body.bin` (~0,8 МБ) — базовая сетка MakeHuman hm08 и формы (пол, вес, грудь, талия, бёдра, шея, плечи, длина ног) под CC0, собран `scripts/makehuman-to-bin.py` (лицензия — `src/assets/MAKEHUMAN-LICENSE.md`). `src/lib/body-model.js` (без three.js, есть тесты): смесь пола и веса по ИМТ → подбор формы «длина ног» под шаговую → масштаб под рост → формы обхватов подбираются, пока срез тела на уровне груди/талии/бёдер/шеи (выпуклая оболочка, как лента) не совпадёт с меркой → стопа растягивается до длины. ~20 мс на телефоне. Рост и вес меняют только пропорции через подгонку, формы роста не нужны. Модель грузится только на экране мерок.
- **Мерки по фото:** `src/photo-measure.jsx` (экран, ленивый чанк) + `src/lib/photo-measure.js` (математика, есть тесты на синтетических «фото» 3D-тела). MediaPipe Pose Landmarker (`@mediapipe/tasks-vision` 1.2.0, только SIMD-сборка `vision_wasm_internal.*` ~14,5 МБ, модель `src/assets/pose_landmarker_full.task` ~9,4 МБ, лицензия — `src/assets/MEDIAPIPE-LICENSE.md`) даёт маску человека и суставы; масштаб = рост / высота силуэта (пол берётся на 1,5 % выше нижней точки — носки на фото с уровня пояса ниже пола под телом); ширина спереди и глубина сбоку на уровнях, где меряет 3D-тело; обхват = обхват 3D-тела × эллипс(фото) / эллипс(3D-тело), два прохода с переподгонкой тела; грудь читается чуть ниже подмышек, если руки касаются; шов — от верха просвета между ногами. Шею и стопу по фото не меряем. Фото не сохраняется и не уходит с телефона; в `body` — `sources: {chest: "photo", ...}` (пометка «по фото», снимается ползунком). Проверено на отрисованном 3D-теле через настоящий MediaPipe: с фото сбоку ±0–3 см, только спереди до −5 см; на живых фото ещё не проверено.

### Ключевые потоки
- **Импорт («＋»):** фото → `detect` → экран выбора (все отмечены) → `POST /jobs/:id/add` для отмеченных, остальные удаляются → `cutout` → автоодобрение (`decide()` в local-api) → вещь в гардеробе. Не решил — не добавляем (при перезапуске нерешённые удаляются, `settleJob`). Ручная помощь только при плохом фоне.
- **Сегодня:** план на день из `plan` (5 образов), замена вещи шторкой, «Без верхней одежды» и плитка «＋ Верхняя одежда», переворот карточки: манекен (`renderOutfit`/`outfitAnchors`, кнопка «В помещении») или «На мне» (`tryon`, кэш по набору вещей). Оценки: «Надену» = лайк, «Другой образ» = причина в один тап.
- **Покупки:** `gaps` (с `part`, `kind`, `color`, `query`) → карточки «+N образов» (считается на устройстве) → «Мой размер»: `sizeForKind(kindOf(gap), bodyOrProfile(body, profile))` из `src/lib/sizes.js` даёт размер в системе, в которой продаётся вещь (буквы для верха, EU для пиджаков, W/L для джинсов и мужских брюк, EU для женских брюк и юбок, EU для обуви; у аксессуаров размера нет), его английская часть дописывается к `query` → предложения: `prices` (если есть ключ) или ссылки на магазины страны (с тем же запросом).

## 3. История проблемы «Нет связи с сервером» (решено 16.11.2026)
Причина: KV `USAGE` не был привязан, Worker падал без CORS. Исправлено: привязка KV в Cloudflare + Worker всегда отвечает JSON с CORS и понятной ошибкой. `http://localhost:5173` в `ALLOWED_ORIGINS` нет — локально запросы к ИИ не проходят (для проверки интерфейса подменяем `fetch` тестовыми ответами).

## 4. Продуктовые решения владельца

- **Утро или вечер:** образ на сегодня или с вечера на завтра; есть «Оба раза».
- **Замена любой вещи** через шторку снизу. Верхнюю одежду и аксессуары можно убрать («Без верхней одежды») и вернуть плиткой «＋».
- **«В помещении»** на манекене — снять куртку, шарф и шапку и посмотреть образ внутри.
- **Чёрная пятница (ноябрь 2026):** сейчас смысл приложения — помочь владельцу и друзьям выгодно докупить вещи в капсулу на Чёрную пятницу, искать прямо в приложении, без ручного поиска. Владелец попросил агрегаторы вроде Zalando для «необычных» вещей (блейзер, кроссовки, футболки).
- **Покупки — главная ставка:** «Чего не хватает» → предложения по цене **с доставкой**, «Новые / Б/у», бейдж лучшей цены, «Сэкономлено за месяц». Цены не выдумываем: без ключа — ссылки на поиск в магазинах.
- **Карточка переворачивается:** «Манекен» с выносками (тап по выноске — замена, карточку не переворачивать) / «На мне» (ИИ-примерка, только по кнопке).
- **Примерочная:** с фото человека — только лицо и фигура, вещи списком в порядке слоёв, одна поза (прямо, руки вдоль тела), светлая студия. Фото целиком, по тапу — на весь экран. Позже: базовое студийное фото, смена фона за картинку.
- **Импорт:** один экран выбора на фото; без проверок кадра и вырезки; фото «на мне» для каждой вещи выключено (позже премиум).
- **Названия «цвет + тип»:** «Чёрный бомбер», «Серебряная цепочка». Аксессуары и украшения распознаются.
- **Бренд** вещи пишет сам пользователь.
- **Оценка:** лайк/дизлайк + причины в один тап, каждый тап подтверждается («Запомнил: …»). 10-балльную шкалу и игровые механики (серии, награды, кольца) владелец отклонил.
- **Палитра** по селфи → в «Мой стиль»; карточка для сторис; «Найти вещи в моих цветах» → Покупки.
- **Первый запуск:** знакомство за минуту (пол, рост, вес, стиль, первые вещи), всё можно пропустить.
- **3D-аватар:** владелец выбрал **параметрическое 3D-тело** (ползунки/мерки, рисуется на устройстве, без своей 3D-модели на каждого). 16.11.2026 одобрил скачать открытую модель MakeHuman (CC0) — теперь тело реалистичное, на нём базовый боди (у мужской фигуры — шорты), тело само поворачивается к выбранной мерке.
- **Стилист (16.11.2026):** владелец хочет промпты «как у стилистов» и объяснения маленькими всплывающими подсказками. Палитра — система 12 сезонов (Sci/ART, Kathryn Kalisz: тон, светлота, насыщенность по Манселлу + контраст), у каждого цвета `why`, черты лица `traits` (чипы), `photoNote` про свет. Образы — `STYLIST_RULES` в Worker (60/30/10, цвета палитры у лица, контраст как у человека, правило трети, баланс объёма, одна ступень формальности, фактуры) и `tips` (1–2 совета-чипа к образу, `HintChips` в `src/ui.jsx`). Это общепринятые правила стилистов из блогов и школ, не стандарт — модель может отступить, если так лучше.
- **Стабильная палитра (18.11.2026):** у похожих людей должны быть одинаковые цвета → фиксированные веера 12 сезонов; калибровка белым листом с объяснением зачем (владелец сомневался, не странно ли просить лист, — лист необязателен). Модель лица (MediaPipe Face Landmarker) и «Список на Чёрную пятницу» — позже.
- **Английская версия (18.11.2026):** владелец: «нам надо будет 100% завести английскую версию». Интерфейс сейчас только русский; шрифты уже подходят.
- **Размеры без ленты (18.11.2026):** владелец: людям, живущим одним, важно не мерить себя самим (±2–4 см достаточно). Порядок: 1) размер без замеров (обычный размер, бирки, «впору/мала/велика», «Как сел размер?»), 2) авто-съёмка с голосовыми подсказками, после фото — палитра по лицу с этого же фото (по желанию) и фото для примерки, 3) тип фигуры и крой — позже. Проверку точности лентой на друзьях владелец сделает сам после пунктов 1–2. Таблицы размеров магазинов — потом.
- **«Покупки» (19.11.2026):** сравнение цен — только Zalando и About You (2 поиска); все магазины — плитки-ссылки с фильтрами; SHEIN — плитка (пол, цвет, тип в запросе, размер кодом SHEIN). Позже, может быть: SHEIN в «Сравнить цены» через Google Покупки (+1 поиск). Палитру владелец хочет оформить красивее — думает. ИИ-примерка: шарф «прилипает» к худи, модель выглядит неестественно — владельцу не понравилось, разобрать позже.
- **Партнёрские ссылки (обсуждено 18.11.2026):** идея — комиссия с покупок по ссылкам магазинов. Подключать при открытом запуске, не для друзей. Порядок вещей не зависит от комиссии (только цена, размер, скидка); партнёрская ссылка помечается.
- **Палитра:** владелец хочет не объяснять цветотип текстом, а показывать селфи рядом с цветами. Маленькая копия селфи хранится только на устройстве (`blobs`, ключ `palette-selfie`), есть «Удалить фото».

## 9. Правила работы

- **Коммит = выкладка.** Push в `main` сразу публикует сайт. Коммитить и пушить **только после явного «коммить»** владельца. Перед коммитом: `npm test` и `npm run build`.
- **Worker обновляется вручную:** после изменений `proxy/worker.js` сказать владельцу, что нужно вставить файл заново (Cloudflare → Edit code → Deploy), и дать ссылку на файл — полный текст в чат не нужен (18.11.2026). Невидимые символы в коде писать как `\uXXXX`.
- **В магазины и в поиск — только английский** (18.11.2026): интерфейс русский, а запросы, ссылки и всё общение с магазинами — на английском.
- Владелец сам просматривает файлы: объясняй изменения, не добавляй зависимости без причины, называй каждую новую библиотеку.
- Никогда не клади ключи и коды доступа в код, коммиты или логи.
- Все промпты и выбор моделей — только в Worker. Ограничение «только одежда» не ослаблять (в том числе для поиска цен).
- Не показывать выдуманные данные (цены, погода, экономия): лучше честная заглушка или ссылка.
- Проверка интерфейса: `npm run dev` + встроенный браузер; ответы Worker подменять в странице (`window.fetch`), тестовые вещи класть в IndexedDB.
